# 깨달음의 가루 최적화

원신(Genshin Impact) 성유물 계산 파일럿 웹앱. 등록, 캐릭터 스펙 계산, 재구축(계몽의 먼지) 추천까지 한 페이지에서 처리합니다.

정적 HTML/CSS/JS 파일로 동작하며 빌드 과정이나 직접 만든 서버, 패키지 매니저가 필요 없습니다 (로그인·저장은 Firebase라는 외부 서버리스 백엔드를 씀 — 아래 "로그인 / 데이터 저장" 참고). 파일을 그대로 정적 호스팅(GitHub Pages 등)에 올리면 끝입니다.

## 파일 구조

```
index.html          — 페이지 뼈대 (마크업만, 데이터·로직 없음)
style.css            — 전체 스타일
firebase-config.js   — Firebase 프로젝트 설정값 (직접 채워넣어야 함, 아래 참고)
data.js              — 고정 데이터: 성유물 슬롯/부옵션 정의, 롤 값 테이블, 세트 목록,
                        캐릭터 레지스트리(CHARACTERS), 재구축 상수 등
app.js               — 로그인·화면 렌더링·저장·시뮬레이션 로직 전체
data/imgs/artifacts/   — 성유물 부위·세트 아이콘 (flower.png, feather.png, sands.png,
                          goblet.png, circlet.png, night.png 등 — 직접 추가)
data/imgs/characters/  — 캐릭터 아이콘 (flins.png 등 — 직접 추가)
```

`index.html`이 `data.js` → `app.js` 순서로 불러옵니다. 두 파일 다 모듈이 아닌 일반 스크립트라 `data.js`의 최상위 상수(`CHARACTERS`, `SLOTS` 등)를 `app.js`가 그대로 참조합니다 — 번들러나 `import`/`export` 없이도 동작해요.

부위/세트/캐릭터 선택 드롭다운은 네이티브 `<select>`가 아니라 아이콘을 보여주기 위한 커스텀 드롭다운(`app.js`의 `mountIconSelect`)입니다. `data.js`에서 `icon` 값이 `.png`/`.jpg`/`.svg`/`.webp`로 끝나면 이미지로, 아니면(이모지 등) 텍스트로 렌더링됩니다.

## 호요랩 붙여넣기로 등록하는 법

호요랩(또는 게임 내) "캐릭터 정보" 화면에서 성유물 5부위가 보이는 부분을 **한 번에 5개 다** 드래그해서 복사한 뒤, "호요랩 붙여넣기로 등록" 칸에 붙여넣으면 자동으로 파싱해서 등록됩니다.

**부위 판별은 이름이 아니라 주스탯 종류로 합니다** — 이름을 일일이 등록할 필요가 없어요. 게임 규칙상 아래 5가지는 절대 겹치지 않아서 100% 정확하게 판별돼요:

| 주스탯 | 부위 |
|---|---|
| HP (고정치) | 꽃 |
| 공격력 (고정치) | 깃털 |
| 원소 충전 효율% | 시계 |
| 치명타 확률% / 치명타 피해% / 치유 보너스% | 왕관 |
| 원소 피해% / 물리 피해% | 성배 |

공격력%/HP%/방어력%/원소 마스터리만 시계·성배·왕관이 다 가질 수 있어서 유일하게 애매한데, 이건 **이 배치 안에서 아직 안 쓰인 슬롯을 시계→성배→왕관 순서로 배정**해서 풉니다 (캐릭터 정보 화면은 항상 꽃→깃→시계→성배→왕관 순으로 나열되므로, 5개를 한 번에 붙여넣는 걸 전제로 함).

세트는 `data.js`의 `NIGHT_SET_PIECE_NAMES`에 등록된 이름("진실 갈망의 꽃" 등 "하늘 경계가 드러난 밤" 세트 5개 고정 이름)과 일치하면 그 세트로, **그 외 이름은 전부 "오프셋"으로 자동 분류**됩니다. 오프셋 쪽은 실제 세트가 뭐든 상관없이 그냥 "경계셋이 아닌 나머지 한 자리"로만 취급하는 게 의도라, 이름 사전을 계속 늘릴 필요가 없어요.

```js
const NIGHT_SET_PIECE_NAMES = {
  "진실 갈망의 꽃": "flower",
  // 이 세트는 5부위 이름이 고정이라 한 번 다 채워두면 유지보수 끝
};
```

장착 캐릭터는 자동으로 "캐릭터 스펙" 탭에서 현재 골라둔 캐릭터로 채워지고, 부옵션 4개 미만으로 인식되거나 주스탯으로도 부위 판별이 안 되면 그 항목만 건너뛰고 나머지는 정상 등록되며 결과 메세지에 이유가 표시됩니다.

**한계**: 5개를 한 번에 붙여넣는다는 전제가 깨지면(예: 딱 1개만 따로 붙여넣기) 애매한 주스탯(공격력%/HP%/방어력%/원소 마스터리)을 가진 미등록 이름 피스는 부위 판별이 부정확할 수 있어요 — 이 경우 등록 후 "수정" 버튼으로 부위만 고쳐주면 됩니다.

## 캐릭터 추가하는 법

`data.js`의 `CHARACTERS` 배열에 객체 하나만 추가하면 됩니다:

```js
const CHARACTERS = [
  {
    name: "플린스",
    icon: "data/imgs/characters/flins.png",
    atkByLevel: { "80/80": 310, "80/90": 326, "90": 352, "95": 391, "100": 431 }, // 돌파 단계별 기초 공격력
    charBaseCritDMG: 88.4,   // 최대 돌파 이후로는 레벨과 무관하게 고정
    weaponBaseATK: 674,
    weaponBaseCritRate: 22.1,
  },
  {
    name: "새캐릭터",
    icon: "data/imgs/characters/new.png",
    atkByLevel: { "80/80": 0, "80/90": 0, "90": 0, "95": 0, "100": 0 },
    charBaseCritDMG: 0,
    weaponBaseATK: 0,
    weaponBaseCritRate: 0,
  }, // 추가 예시
];
```

`atkByLevel`의 키는 `CHAR_LEVEL_OPTIONS`(`"80/80"`, `"80/90"`, `"90"`, `"95"`, `"100"`) 다섯 단계를 그대로 써야 캐릭터 스펙 탭의 "캐릭터 레벨" 드롭다운과 맞물립니다.

추가하면 "장착 캐릭터" 드롭다운, 캐릭터 스펙 탭의 캐릭터 선택, 재구축 탭의 활성 세트 판별까지 전부 자동으로 그 캐릭터를 인식합니다. 아이콘 파일을 `data/imgs/characters/`에 넣지 않으면 그 캐릭터는 아이콘 없이(빈 이미지) 표시돼요.

## 기능

- **성유물 추가/보유 성유물**: 부위/세트/장착 캐릭터/부옵션을 등록·수정·삭제. 호요랩 "캐릭터 정보" 화면을 통째로 복사-붙여넣기 하거나, JSON으로 여러 개 한 번에 등록·내보내기 가능.
- **캐릭터 스펙**: 부위별로 성유물을 골라 최종 공격력 / 치명타 확률 / 치명타 피해 / CV(2×치확+치피)를 계산.
- **재구축 추천**: 보유한 5★·풀강 성유물마다 재구축(치확·치피 우선)했을 때의 CV 기대 상승치를 **정확한 확률분포 계산**(롤 하나하나의 이산분포를 컨볼루션)으로 구해서, 가루 1개당 기대 상승치가 큰 순서로 추천. 몬테카를로 방식이 아니라서 버튼을 몇 번을 눌러도 항상 같은 값이 나옵니다. 하로우드 엑서지시스(6·12·18 보장 롤 상승) 및 4세트 유지(여유 슬롯 포함) 로직 반영.

## 실행 방법

5개 파일(`index.html`, `style.css`, `firebase-config.js`, `data.js`, `app.js`)을 같은 폴더에 두고 정적 파일 서버로 열면 됩니다. 스크립트들이 `<script src="...">`로 로드되기 때문에 `index.html`을 파일로 그냥 더블클릭해서 열면 브라우저 보안 정책(CORS)에 막혀 안 될 수 있어요 — 반드시 로컬 서버를 통해 열어주세요. Firebase SDK는 CDN에서 불러오므로 인터넷 연결이 필요합니다.

```bash
# 예: 로컬에서 간단히 띄우기
python3 -m http.server 8000
# http://localhost:8000 접속
```

## GitHub Pages로 배포하기

1. 이 저장소의 Settings → Pages로 이동
2. Source를 `main` 브랜치 / `root` 폴더로 설정
3. 저장하면 `https://<사용자명>.github.io/<저장소명>/` 에서 접속 가능

## 로그인 / 데이터 저장

아이디(내부적으로는 이메일로 변환됨)+비밀번호로 로그인하는 계정별 저장 방식입니다. **Firebase**(Google의 서버리스 백엔드: Authentication + Firestore)를 씁니다 — 별도 서버를 만들 필요 없이 정적 사이트에서 바로 씁니다.

### 처음 설정하는 법

1. https://console.firebase.google.com 에서 새 프로젝트 생성 (무료 Spark 요금제로 충분)
2. 왼쪽 메뉴 **Authentication** → "시작하기" → 로그인 방법 탭에서 **이메일/비밀번호** 활성화
3. 왼쪽 메뉴 **Firestore Database** → 데이터베이스 만들기 (프로덕션 모드, 리전은 아무 곳이나)
4. **Firestore 규칙** 탭에서 기본 규칙을 아래로 교체:
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /users/{uid}/{document=**} {
         allow read, write: if request.auth != null && request.auth.uid == uid;
       }
     }
   }
   ```
   (로그인한 본인의 데이터만 읽고 쓸 수 있게 막는 규칙입니다.)
5. 프로젝트 설정(톱니바퀴 아이콘) → 일반 탭 → "내 앱"에서 웹 앱 추가(`</>` 아이콘) → 나오는 `firebaseConfig` 객체를 통째로 복사
6. 이 저장소의 `firebase-config.js`를 열어서 `firebaseConfig` 안의 `YOUR_API_KEY` 등 자리에 그대로 붙여넣기

이 값들(apiKey 등)은 브라우저 코드에 그대로 노출돼도 괜찮은 공개 식별자입니다 — 실제 접근 제어는 4번의 Firestore 규칙이 담당합니다.

### 로그인 화면

- 아이디는 영문/숫자/밑줄 3~20자, 비밀번호는 6자 이상이어야 해요.
- 화면엔 "아이디"만 보이지만, 내부적으로는 `아이디@artifact-ledger.local` 형식의 가짜 이메일로 Firebase Auth에 등록됩니다 (도메인은 `firebase-config.js`의 `AUTH_FAKE_EMAIL_DOMAIN`에서 바꿀 수 있어요).
- `firebase-config.js`를 아직 안 채웠으면 로그인 화면에 안내 문구만 뜨고 앱은 안전하게 대기 상태로 머뭅니다.

### 데이터 옮기기 / 백업

"성유물 추가/보유 성유물" 탭의 "내보내기" 버튼으로 로그인한 계정의 전체 데이터를 JSON 파일로 다운로드할 수 있고, 같은 형식을 "가져오기" 칸에 붙여넣으면 다른 계정으로도 복원/이전이 됩니다.

## 알려진 가정치 / 한계

- 부옵션 롤 값(치확·치피)은 공개된 커뮤니티 참고치를 사용했어요. 패치에 따라 실제 값과 미세하게 다를 수 있습니다.
- 하로우드 엑서지시스(고급/계시 재구축) 판정은 "진행도 0~17, 18에서 리셋"이라는 관찰된 동작을 기준으로 구현했습니다.
- 세트 효과 자체는 CV 점수에 반영하지 않고, 재구축 추천 시 "현재 4개 이상 차지하는 세트 + 남는 여유 슬롯"만 후보로 필터링하는 방식으로 우회했습니다.
- 캐릭터/무기 기초 스탯은 `data.js`의 `CHARACTERS` 배열에 캐릭터별로 등록하는 구조라, 지금은 플린스 한 명만 들어있어요.
- 아이콘 이미지 파일(`data/imgs/...`)은 저장소에 포함돼 있지 않습니다 — 직접 추가해야 드롭다운/목록에 아이콘이 보입니다.
- 로그인/Firestore 연동 코드는 실제 Firebase 프로젝트가 있어야 동작이 확인되는 부분이라, 코드 자체의 문법 오류나 UI 전환(로그인 화면 ↔ 앱 화면)은 검증했지만 실제 회원가입·로그인·저장까지 엔드투엔드로 테스트하진 못했어요. `firebase-config.js`를 채운 뒤 회원가입부터 한번 직접 확인해주세요.
